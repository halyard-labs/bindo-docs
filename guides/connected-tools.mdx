---
title: Connect Bindo to other MCP servers
description: Give the assistant reviewed lookup tools from your existing systems.
---
This is the other direction of MCP: **Bindo is the client**, and your booking or repair system provides tools.

<Steps>
<Step title="Prepare a narrow credential">
Choose a trusted Streamable HTTP MCP server. Use a provider credential that can only read the intended business records. Your administrator stores its bearer token in Bindo's private configuration, bound to the exact endpoint URL, and gives you its reference. Anonymous public servers do not need a credential reference.
</Step>
<Step title="Connect and discover">
In **Business → Reply settings → Tools**, add a connection name, public HTTPS endpoint and optional credential reference. Select **Discover tools**. Discovery leaves every tool disabled.
</Step>
<Step title="Review each lookup">
Read the tool description and argument schema. Verify its actual behaviour and data access with the provider. A server's read-only hint is only a claim. Approve only tools that cannot change records or send messages.
</Step>
<Step title="Check runtime support">
The hosted OpenAI runtime can select up to three reviewed read-only lookups, executed by the backend. Drafts retain their arguments, results and lookup time for staff review. Account-specific results do not qualify for automatic sending. The optional Bedrock runtime also supports reviewed lookups.
</Step>
</Steps>

The pilot allows five connections, 20 discovered tools per server, 12 enabled tools per draft and three lookup calls per generation. Results and execution time are bounded. Changed tool definitions require rediscovery and approval again. Rediscovery resets all permissions for that connection.

Remote servers receive the arguments passed to their tools. Only connect providers you are authorised to share customer details with. Bindo blocks private network targets and redirects, and does not forward its workspace token to remote servers.

OAuth, local stdio servers, automatic provider selection and state-changing tools are not available yet. A server with broad administrative tools is not safe merely because it supports MCP.

### Product account context

For account-scoped support connections, staff verify and link the customer account under **Customer details → Connected accounts**. The backend supplies that account identity to the tool; customer messages cannot choose another account. No link means no account lookup. Cancellation previews change nothing and must be reviewed in the product by authorised staff.
