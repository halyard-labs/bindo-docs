---
title: Authentication
description: Use a separate workspace credential for each person or agent.
---
Connect an agent to `https://app.bindo.ai/mcp` using OAuth in a client supporting dynamic client registration and PKCE. Sign in with your existing Google/email account, choose a workspace and approve the requested permissions. Disconnect agents under **Settings → Agent access**. Grants expire after 30 days and cannot exceed your current workspace permissions.

OAuth access tokens are for the customer workspace MCP only: they cannot call the ordinary REST API or the privileged support-admin MCP. OAuth does not create new workspaces or grant paid access.

Administrator-provisioned `Authorization: Bearer <workspace-token>` credentials remain supported by the API and MCP. These are a separate authentication path.

Never put a token in a URL or a published document. Keep agent tokens in your client's secret store or environment. Revoke them by removing their hash from Bindo's private runtime configuration.

| Permission | Purpose |
| --- | --- |
| `customers:read` | Customer history, enquiries, drafts and reply rules |
| `drafts:write` | Create or generate reply drafts |
| `knowledge:read`, `assistant:read` | Read approved knowledge and assistant behaviour |
| `integrations:use` | Let generated drafts call staff-approved connected lookups |
| `integrations:read` | Inspect connected servers and tool permissions |
| `integrations:write` | Configure servers and discover tools; agents cannot approve tool permission grants |
| `billing:read` | Read subscription state |

Configuration also has separate scopes for knowledge, assistant, enquiry, channel and reply-rule changes. Use explicit scopes; a wildcard agent token does not grant management permissions.

<Warning>
Use dedicated `agent` credentials for external agents. Sending replies, granting tool permissions, Checkout and billing-portal access require a human operator. MCP calls cannot exercise these privileges even with an operator token.
</Warning>
